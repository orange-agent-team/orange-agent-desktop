# 中断编辑检查（候选实现）

当前候选固定使用 Runtime64748cd25940b9bef28d1efd90488a8e8ab76684。主线仍使用已经验收的81bf2d9；本候选尚未合并。

## 用户流程

打开“中断编辑检查”，查询运行并选择尚未解决的文件编辑操作，再通过独立目录选择授权读取。界面显示本次检查时当前文件、待发布文件和保留原件的状态，以及可展开的内容/权限属性摘要。内容匹配不会被显示成原操作已确认完成，旧任务不会自动继续。

“结束恢复检查”立即清除界面内容，随后等待Rust读取租约排空，再释放native目录选择。关闭、撤权、切换运行或迟到回调不能重新显示旧快照。释放未确认时保留错误和native持有关系，不伪称权限已经释放；native窗口仍是最终资源拥有者。

只检查时不会执行恢复写入。另行选择写入目录后，可核对“保留当前文件”“把保留原件放回空缺位置”“把待发布版本放到空缺位置”三种实际决定；必须再批准当前实际预览摘要才执行。原件管理/数据退出仍待接入。

## 接口与信任边界

- `listUnresolvedEdits`：仅返回当前拥有者、指定Run的操作ID，支持有界分页，不恢复文件权限。
- `authorizeRecoveryInspection`：可信UI必须先进行独立native选择；带Run/operation、选择ID、预期workspace权限版本和目录。使用独立PatchInspectionGrant，不能成为普通Run或编辑授权。
- `inspectRecovery`：仅凭当前检查scope读取实际快照；投影核对operation，省略原件/暂存内部名称和文件内容。Root版本、scope生命周期和Host epoch都参与拒绝旧访问。
- `suspendRecoveryInspection`：先队列外撤权，再排空和释放；未知或迟到选择也关闭其ID。其他用途的选择ID不能冒充检查选择。

工作区整体撤权会处理独立检查scope，即使普通WorkspaceSignal在Host重开后不存在。控制器绑定不可变Host句柄，选择器、授权和检查结果带界面世代核对；失效结果释放权限而不重新显示内容。

## 恢复决定与回执

`authorizeRecoveryWriteAccess` 和 `suspendRecoveryWriteSelection` 管理单独的写scope；不能复用读取选择ID。读取scope关闭、整体工作区撤权或Host关闭会撤销关联写scope；释放写scope本身不扩大或恢复读取权限。

`prepareRecoveryDecision` 从Runtime获取实际当前快照和决定摘要。`approveRecoveryDecision` 仅接受该写scope当前预览的ID/digest；旧预览、错误摘要、撤权和重复调用被拒绝。完成后保持原操作unknown及旧Run停止，其他保留版本不被删除。UI对“放回原件”额外要求其内容仍匹配原始版本。

`inspectRecoveryOutcome` 不需要恢复文件权限，只核对拥有者/Run/操作绑定及持久回执摘要，返回决定ID/choice和原操作状态，不返回文件数据。丢失批准回复时只查询它，不重发批准；没有回执仍显示结果不确定，不等于没有文件变化。

实际原生三选择测试96098 exit0，涵盖最终回执故障及捕获原文件后的阶段回执故障。保留、放回、发布均检查真实文件和保留版本；放回原件场景在真实提交后用测试包装器丢弃回复，界面仅查询一次回执，批准调用仍为1。模型/选择器为明确替身，不是生产签名、人工系统选择器或跨OS认证。验收入口为`scripts/check-recovery-decisions.py`，组合验收37915 exit0（recovery-decisions-acceptance.log）；新增不可变决定一致性断言通过62797相关组件复验。
