# 报价确认稿

PRD-004.02 对应的确认界面分为上传预览与费用确认。第一次点击允许平台接收预览字节并计量，平台费用和预留均为 0。第二次点击才授权对原报价冻结开发积分。待核对状态在界面中保留原请求编号。

| 确认时的字段 | 来源及展示规则 |
|---|---|
| 输入和执行方 | 原上传版本/摘要、调用编号、节点、审核模型版本；音频再显示观测、地区、时长及每分钟费率 |
| 最高费用 | 原报价 max_amount，使用整数微积分。显示价格版本、有效期和输出计费上限。转写按毫秒向上取整，公式见下 |
| 费用归属 | 真实 owner_id、个人或团队，以及 root_budget_id。普通成员看到本人分配的预算与支付条件；账户余额仅在服务端允许披露时显示 |
| 截至当前已占用 | 服务端返回的预算总额、累计已用和已预留；可用额度等于总额减累计已用再减已预留 |
| 确认后的上限 | 当前可用额度减本次最高预留。已有环节继续使用原根预算。每笔报价仅授权本次步骤 |
| 超限、过期或暂停 | 余额不足、预算不足、账户消费暂停及报价过期分别说明。禁用提交，用户可减少输出、选择有权使用的预算或重新询价。资金查询失败时保留原请求供核对 |

**确认稿示例。** 授权录音长 11,000 毫秒，报价为每分钟 12,000 微积分。最高预留为 ceil(11,000 × 12,000 / 60,000) = **2,200 微积分**。确认按钮旁显示所属账户、预算和该上限。查询报价不扣款；实际结算额取决于已交付结果和计量回执。取消后查询原作业及原预留释放状态。

**重复与恢复。** 点击提交前重新核对原报价、有效期与当前资金条件。请求回执丢失时先按原调用查询。报价键、调用、输入和付款方均保持绑定。线上余额可能在两次读取之间变化，服务端在同一事务中检查可用额和冻结金额。
