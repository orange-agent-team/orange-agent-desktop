# 隐私与累计预算场景评审

PRD-004.04 的评审对象是可见的文案、按钮与状态。以下为工程走查及可执行算例。真实试点中的读者理解率须另行采集。

| 场景与问题 | 用户点击前应能回答 | 验收观察 |
|---|---|---|
| 本地会议文件含联系人邮箱，仅请求本机摘要。哪些字节会离开工作区？ | 读取需工作区授权和本次批准；本地模型处理文件内容。下载模型时传输的是模型文件。没有向平台上传会议文件的请求 | 在本机运行模型；检查缺文件和取消下载时没有远程推理退路 |
| 在 Web 预览联系人片段的遮盖文本。节点和平台会看到什么？ | 平台在用户批准上传后收到预览中的精确字节，执行节点在提交后可读这些明文。原邮箱不应出现，其他身份线索仍可能存在 | 对实际 PUT 求摘要并对比预览；修改原文本后旧提交按钮失效；检查恢复存储不含原文或遮盖词 |
| 团队成员有 10,000 微积分预算，已用 2,200，其他在途预留 1,000。下一步摘要报价最高 3,000，能花多少？ | 当前可用 6,800，新步骤最多预留 3,000，预留后还可用 3,800。已完成的转写与这次摘要合计最多 5,200；另一个在途作业单列 | 用同一 root_budget_id 计算。若摘要实际结算 1,400，累计已用变为 3,600、其他预留仍为 1,000，可用额度恢复为 5,400 |
| 报价已返回，管理员此时撤回成员资格，还能提交吗？ | 旧页面上的报价不能增加当前权限。核对失败时应关闭表单或阻止提交，个人钱包不会承接团队支出 | 双浏览器验证撤权后打开的任务表单消失；未发送草稿产生零次上传 |
| 11 秒录音按每分钟 12,000 微积分报价，网络丢失两次回执。会重复收费吗？ | 本次最高预留 2,200 微积分。先核对原报价或原作业，不能因刷新重新批准消费 | 浏览器丢失报价回执后，以相同请求编号取得相同报价；丢失提交回执后恢复到同一 Job，实际提交一次 |

**评审结论。** 用户要在两个时点作出不同决定：上传前核对准确字节与目的地，消费前核对付款方和最高预留。示例中的两步骤金额用于验算界面，不能充当 AU-04 转写后自动生成纪要已经上线的证明。已有实际托管 Agent 后续模型步骤验证了原根预算与累计已用，团队文本、转写和资源下载另有独立回归。
