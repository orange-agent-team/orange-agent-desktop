# 桌面任务使用本地记忆

在本地记忆面板打开一个空间，然后在会话面板为新任务选择读取权限。若要让模型提出记忆修改，还需打开编辑访问并在任务里勾选允许修改。每个工具请求单独批准。写入预览展示目标条目、版本、正文、启停状态及其来源。删除也需核对预览。

记忆会话允许选择额外的工作区和记忆空间以验证派生内容。Host 将这些验证来源与模型可读取的空间分别传给 Runtime。持久任务记录决定恢复所需的空间、版本和读写模式。重启后先恢复工作区，在记忆面板打开相应空间，再点击恢复任务访问。当前会话面板可以选一个模型可见空间，原生接口支持最多八个。

每个任务从当前选择派生独立的授权对象。其读取凭据计入任务、用户选择和空间修订三处的生命周期。关闭用户选择会停止所有派生任务的访问。单个任务取消只撤销该任务的权限。工作区与记忆来源的许可变化会清除会话界面缓存。Host 重新读取任务内容时会校验实际来源。

脚本模型与真实 SQLite 的原生集成验证位于 `apps/desktop/integration_test/task_memory_test.dart`。真实 CPU 模型验证使用 `scripts/check-real-run.py`，读取场景传入 `--memory`，写入场景传入 `--memory-write`。两者分别要求模型返回自有测试条目的随机正文，以及提交一个经过精确批准、内容与版本都能从 SQLite 核对的新条目。运行报告记录模型哈希及真实结果。

任务写入中断时，可以按任务和操作标识查询已保存的草稿回执。界面根据回执显示提交状态和结果版本。选择继续时，Host 重新校验该任务的权限和来源。选择结束时，任务所有者可以在关闭记忆访问后按回执结束任务。Runtime 在同一个事务中核对操作、摘要、草稿状态和已提交版本，随后记录决定。重复确认会被拒绝。

在本地记忆面板中选择空间后，点击“查找我的待确认草稿”可取回重启前留下的请求。目录显示条目标识和草稿标识。打开编辑访问才能重新审阅正文。确认作废会清除待提交内容，同时保留无正文的回执和审计记录。

本地 llama.cpp 接口会为新任务分别提供读取正文、列举条目、新增、更新和删除函数。适配器从任务已协商的参数定义中复制空间枚举和字段约束。只读任务在本地模型接口上只出现条目读取、范围读取及列举函数。Runtime 仍按 memory_read.v2 和 memory_write.v1 记录意图、来源与批准。函数名称和参数在两种表示之间往返时保留调用 ID。拒绝名称冲突、额外控制字段及未获授权的空间。

任务创建时保存的系统工具说明决定本地投影版本，历史会话继续使用创建时的表示。计量请求和流式生成使用同一份投影后的模型输入。原生应用测试仍通过相同的 Host、Runtime 和 SQLite 路径，单动作函数只存在于本机模型传输边界。

本轮已在 macOS ARM64 上使用 Qwen2.5-0.5B-Instruct Q4_K_M 验证桌面 Rust Host 的实际 CPU 推理。模型文件 SHA-256 为 `74a4da8c9fdbcd15bd1f6d01d621410d31c6fc00986f5eb687824e7b93d7a9db`。读取和写入各使用一个临时库、两次模型调用、一次测试所有者批准。读取用例从已批准的工具结果中取得随机正文，还验证了重开后的显式授权和撤权。写入用例必须以精确预览批准新记忆，并用版本 1 从 SQLite 读回匹配的正文。运行器使用私有 Unix 套接字，退出时核对模型停止回执。

`scripts/check-managed-model.py --ui-memory-only --model PATH` 将同一个已固定文件临时加入开发测试包，运行应用内的真实模型交互。该脚本在退出时还原暂存的组件包。随后运行 `scripts/check-flutter.py` 可生成默认入口的开发应用并核对签名与组件指纹。
